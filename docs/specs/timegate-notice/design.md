# 时光之门文字通知设计

## 实现选择

- 为五个 LCD 分别生成 GIF，再用 `Device/PlayGifLCDs` 一次下发。短素材可以本地循环，预览与动画复用同一套排版。
- 用自定义表盘元素显示文字。设备能渲染文字和背景，闪烁和精确排版取决于固件能力。
- 电脑逐帧推图。修改方便，已有屏间延迟和 Loading，持续产生网络流量。

采用五个 GIF 的方案。页面显示简洁的设备示意、实时预览、文字输入、灯光选色和发送入口。服务端按完整字符分配屏幕，按最大可用字号渲染，尽量居中使用连续的屏幕。支持中文和常用拉丁文字，过长文字按同样的规则缩小或换行。预览使用编码 GIF 的同一张亮帧。

表情包使用一块独立的屏幕，单独发送时居中，和文字一起发送时放在文字右侧。支持 GIF、PNG、JPEG 和 WebP，保留宽高比，透明区域使用屏幕底色。动图转换为最高 8 秒的循环 GIF，过快的帧会采样。静态表情保持显示，文字继续闪烁。

服务器发出一次全屏播放请求，用独立地址提供五份循环素材。资源服务标记每屏下载是否结束，页面显示设备回执和下载结果。呼吸灯优先验证全区呼吸档位与固定色，峰值 `100`。若原生周期不同，再验证以两秒为周期调光的可行性，按实际结果注明允许的误差或原生周期限制。

开始前读取厂商接口记录的当前整机表盘或独立屏组，并将恢复信息写入本地文件。五份素材成功拉取后，通知播放最多 30 分钟。用户可以立即请求恢复并标为已读。手动恢复成功后显示「已读」，自然到期显示「已到期」。设备的本地时钟查询在五块屏上均返回 `182`，厂商记录的整机表盘是已在目录中确认的 `832`。恢复以有模式字段的通道记录为准。临时播放的外部素材没有可读取的恢复数据。获取不到可靠通道信息时保留当前画面。一次只处理一个通知。发送失败立即恢复，服务重启继续未完成的恢复。

设备最右侧屏幕的右下角用上海时区 `HH:mm` 显示发送时间。文字闪烁和表情动画的每一帧都保留时间，排版留出独立区域。

## 接口与部署

页面和设备 GIF 共用服务端口 19001。`POST /api/sticker` 接收不超过 4 MiB 的图像，返回临时标识和设备使用的 GIF。`POST /api/preview` 和 `POST /api/send` 接收文本、颜色和可选表情包标识，前者只生成预览，后者发播放和灯效指令。`POST /api/restore` 可按通知标识提前恢复，也可以省略标识来恢复当前通知。`GET /api/status` 提供下载、倒计时、恢复状态和已读状态。控制页面使用带随机访问码的内网入口，设备素材通过每次发送独立的随机地址读取。本地令牌只保存在服务器配置中。

桌面自动化使用独立的 `GATE_API_KEY`，通过 URL 查询参数 `key` 访问发送、表情上传、状态和恢复接口。浏览器请求仍验证其来源。

通过用户级 systemd 持续运行，设备地址默认 `http://mir.xclz.tech:19000/divoom_api`。配置包括监听地址、端口、设备可访问的素材基址和控制入口访问码。空仓库无迁移。若设备访问服务器素材失败，记录请求在哪一段断开并验证可用路由，再确认部署结果。

## 验收

验证中英文、短长文本、屏幕边界、HTTP 回执、每块屏素材拉取、预览行为和用户服务重启。真机灯效与闪烁采用可持续观察的测试文字，实际周期以实测为准。
